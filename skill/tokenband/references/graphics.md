# Visual concepts, graphics and image work

Record the purpose, audience/channel, source references, approved product/brand
facts, format, dimensions, transparency and edit invariants. Inspect supplied
references before editing. Choose raster, vector or code-native output according
to the brief and folder rules. Use the relevant installed generation/editing or
design skill and its supported parameters; no universal generator model is
hardcoded here.

Use [routing](routing.md) for common roles, supported efforts, consent and review gates, and [communication](communication.md) for bounded briefs/source packets. A source hash does not replace actual reference inspection or authorize an edit. Keep folder-specific format/channel/tool restrictions and exact edit invariants.

Distinguish new concepts/meaning/claims and fidelity conflicts from approved-layout assembly or deterministic export. Select configured effort and actual capability accordingly; preserve local minimum efforts and task/work-type identifiers. Split mixed scopes coherently or use a route qualified for the demanding part, without lowering aggregate risk or independent QA.

Distinguish the author/reviewer model, generation tool, requested generator model
and tool-confirmed actual generator model. If the tool does not disclose the
actual model, record unknown. Text reasoning effort is not image-generator
quality. A failed tool call does not grant switching to an unapproved paid API.
Preserve real originals and versions; save final assets into the working folder,
not solely in a temporary generator location.

Separate technical QA (dimensions, alpha, format, completeness) from content and
visual QA (product fidelity, proportions, colors, labels, claims, crop,
legibility, hierarchy and conformity to the brief). Independent substantive
visual QA must inspect the actual final images/export. A text-only model cannot
perform visual QA from the author's description. Select a permitted reviewer
with real image access or report the missing capability. Inspect the final file
again after export. New concepts and meaning-changing edits receive independent
QA; deterministic export of accepted material needs only relevant checks.

Map visual requirements to the actual final asset/version and inspected evidence;
record technical checks separately from content/pixel inspection. Prompts,
thumbnails, hashes or author claims do not establish final conformity; missing
source-fidelity confirmation blocks the affected part. Use [lifecycle](lifecycle.md)
for findings/rechecks/intake and [routing](routing.md) for the independent gate.
Acceptance grants no publication/spending; preserve folder channel/action limits.
