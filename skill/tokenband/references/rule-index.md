## Migration checklist

1. Identify authority, accepted package/snapshot and authorized change scope. Preserve prior evidence in the owning folder; do not load history during normal operation or rewrite unrelated projects/configuration.
2. Map each affected current requirement to its bundled file and observable verification. Disposition every removal/move; retain compatible subject safeguards, real runtime limitations and all consent/risk/independence controls.
3. Validate discoverability and conditional triggers, relative links, self-contained text-only packets, provider-neutral paths and conditional host prerequisites. Keep root standard-library worker and native-driver boundaries; do not add mandatory hooks/dependencies or full reference autoload.
4. Compare entry and relevant activated-reference bytes separately from actual/estimated tokens. Include coordination and review overhead; required controls do not depend on a savings claim. New optional complexity must earn its cost on a named workload.
5. Review final identified bytes/evidence independently under the existing gate, resolve/recheck findings, then install only within actual authorization/approval. Preserve frozen baseline and accepted package identity outside the reusable skill. Original wording is preferred; check any imported material's license before inclusion.
