# Step text recovery companion

Use this reference only for the separately installed, reviewed Step Responses text
adapter. The portable skill does not bundle or activate a personal host runtime.
A local release delivery may include the matching host companion; verify its
external file inventory before selecting it. The portable bundle now also includes
[built-in Responses](worker.md#built-in-text-protocols) via `text_responses.py`.
That route needs no companion. Only selection of this separate companion makes
its missing installation a setup prerequisite; it is not permission to silently
use old diagnostic behavior or change a provider.

## Selecting the installed correction

For a new authorized Step text assignment, prefer the reviewed corrected companion
over an older compatible Step text adapter. Its local delivery record identifies
the exact wrapper, runtime inventory and installation directory. Resolve these
from that record, never from a guessed path or the historical family label. Bind
the corrected wrapper and its digest in a new task-scoped adapter/configuration
pair under the existing setup and consent rules. Preserve the original
WORKFLOW_HOME, credentials, saved defaults, receipt identities and unknown owners.
Do not rewrite an existing operation's config, pins or qualification to activate
this correction. A missing compatible binding calls for normal scoped setup, not
a claim that merely copying files switched an existing connection.

Use the [canonical portable chain](setup.md#portable-setup-chain) for the shared
mode/role/grant, credential-reference and preserved-state rules. If selecting this
companion, inspect the separate delivery's complete wrapper/runtime inventory and
reviewed digests, supported platform/transport, existing protected policy/registry
and runtime-config references, credential availability and actual host controls.
Its private host runtime is not imported into the portable package. Bind only the
reviewed compatible adapter and its required admission fields; direct wrapper
evidence does not establish a new bundled adapter bridge's compatibility. Missing
inputs remain explicit, with no guessed service paths or copied credentials.

The companion's wrapper accepts only Step/Kimi text transports and requires the
existing assignment, authorization and config path/digest admission fields. It
provides no file or shell tools. Use the selected host's existing credential and
control mechanism; do not copy example or historical controller configurations.
Native Codex/Claude chat requests, built-in `responses` and legacy `openai-chat`
are separate mechanisms. New task-local built-in Responses selection is explicit,
not an automatic migration from this adapter or legacy Chat Completions. The
companion's optional diagnostics and host behavior remain its own accepted scope;
they do not transfer to another mechanism merely by loading the skill.

## Observed error data

For Step response.incomplete and response.completed with incomplete status, the
corrected adapter preserves optional terminal_metadata: incomplete_reason with
reported/missing/invalid/unknown observation and only max_output_tokens or
content_filter as known values, plus available strict integer usage counts. It
reads only response.incomplete_details.reason and response.usage, never guesses
a cause from a missing field or historical incident.

For request-opening connection failures, transport_diagnostics records the
request_open phase, at most three fixed exception categories and an optional
strict integer errno. This cannot distinguish handshake from transmission or
header wait, and does not prove remote acceptance or termination. Arbitrary
exception strings, class names, IDs, headers and hidden reasoning are excluded.
The shared exception-message sanitizer also removes unknown dynamic class names
from Kimi connection errors; Kimi receives no new optional metadata.

These fields improve diagnosis; they do not fix provider failures, add retries,
increase budgets or authorize another request. Apply [operations](operations.md)
for classification/recovery and [routing](routing.md#apply-routing-to-every-assignment)
for the next-work role decision. Installation, offline QA and
source review are distinct from live host or provider qualification.
