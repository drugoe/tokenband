# Пример: поиск по заметкам

Это вымышленный сценарий для объяснения процесса. Он не является записью реального запуска, скриншотом приложения или измерением качества модели.

Пользователь просит: «Добавь поиск в приложение Notes. Заметки должны находиться по заголовку и тексту».

Менеджер фиксирует постановку в единственном `TODO.md` проекта и открывает постоянный чат задачи: меняется поведение приложения, поэтому задаче нужны отдельный контекст и проверка.

Настроенный исполнитель готовит решение, в котором поиск работает только по заголовку. Независимый проверяющий получает постановку и результат и сверяет требования:

- Поиск учитывает и заголовок, и текст заметки.
- Пустой запрос показывает все заметки.
- Регистр букв не влияет на совпадение.
- При отсутствии совпадений показывается пустое состояние.

Проверяющий обнаруживает пропущенный поиск по тексту. Исполнитель исправляет решение; затем проверяющий повторно проверяет изменённую часть и затронутые требования. Менеджер принимает результат после подтверждения проверки.

Так отдельная проверка помогает обнаружить пропущенное требование до завершения задачи. При простом фактическом вопросе менеджер ответил бы напрямую, без создания чата задачи.
