# TokenBand 0.6.11 — experimental

Version **0.6.11**, revision **20261120.6** · [MIT](../../LICENSE)

This cumulative update includes all accepted package changes since 0.6.6:

- **0.6.7:** substantive milestone results shown in the human conversation.
- **0.6.8:** continue an existing setup conversation, ask only for missing choices, and avoid a mandatory wizard.
- **0.6.9:** invalidate stale cleanup evidence and complete supported owned cleanup through repeated SIGTERM.
- **0.6.10:** Kimi Code skill discovery and state-preservation guidance; no bundled Kimi-native driver.
- **0.6.11:** default continuation of already authorized reversible local work after at most 900 seconds of uncertainty. No separate project activation or required exact terminal/cleanup proof; preserve previous records and versions, continue in a work copy when old writes remain possible, and reconcile/integrate through the manager. Polls and restarts do not restart the same deadline.

This is an instruction policy, not a new scheduler, runtime or automatic process kill. It depends on an executing manager and an available authorized capable executor. Under full access a working copy is not enforceable isolation. Known conflicting ongoing writes can prevent reliable canonical integration; Stop, actual denials, provider/action consent, review gates and uncertain external effects remain binding. Unknown payments/publications are never replayed.

The new recovery policy was checked through static instructional decision scenarios and two independent final reviews. This is not all-model, runtime or GUI proof. Existing cleanup runtime evidence belongs to 0.6.9; executable code is unchanged from that accepted version. Already running turns need to read the updated rules; no automatic reload is claimed.

## Русский

Выпуск объединяет принятые изменения 0.6.7–0.6.11: содержательные результаты в разговоре, удобную настройку без обязательного визарда, исправления cleanup, руководство Kimi Code и автоматическое продолжение уже порученной обратимой локальной работы после не более 900 секунд неопределённости.

Менеджер не ждёт отдельно принятой политики проекта или доказанного terminal/cleanup, сохраняет прежние записи и версии, организует рабочую копию при возможности прежних записей, сам сверяет и интегрирует изменения. Опросы и перезапуск не начинают новый срок.

Правило не останавливает процесс физически и не пробуждает неработающий менеджер. Нужен доступный разрешённый исполнитель; рабочая копия при full access не даёт физической изоляции. Stop, реальные отказы, разрешения, независимая проверка и запрет повторять неизвестные внешние эффекты сохраняются. Постоянно пишущий конфликтующий процесс может мешать надёжному применению в общий путь.

Новая политика проверена статическими сценариями решений по инструкциям и двумя независимыми финальными review; это не подтверждение всех моделей, runtime или GUI. Исполняемый код не менялся после принятой 0.6.9. Уже работающим чатам нужно прочитать новые правила; автоматическая перезагрузка не заявляется. Полный Kimi-native цикл остаётся отдельной незавершённой работой.
