## English

TokenBand 0.6.20 is a cumulative instruction update. It incorporates the changes previously numbered 0.6.17, 0.6.18 and 0.6.19 together with the final manager-flow and status-display rules; those intermediate updates are documented here as part of 0.6.20 rather than as separate downloads.

### Manager work without periodic automation

- Manager state checks are part of an actual authorized working turn. Installing the skill or creating, adopting or continuing a manager does not create or require a timer, periodic schedule, reusable hourly prompt, cron job, daemon or self-wakeup promise.
- While useful authorized work, a running assignment or required result intake remains, the manager continues the same actual turn through supported finite observation, result validation and intake, the applicable independent gates, and each authorized ready successor. A status answer or saved report alone does not complete that coordination goal. This permits neither indefinite unchanged polling nor a reciprocal acknowledgement loop.
- Editing these instructions does not disable or delete an existing timer. Any action on an exact pre-existing timer remains a separately authorized host operation and leaves other user automation untouched.
- Stop remains immediate. The non-resetting 900-second uncertainty deadline and the existing recovery, original-ownership, actual-denial, UNKNOWN and non-replay rules are unchanged.

### Task and manager titles

- Active standalone work contributes exactly one `0` to the manager's active-work display. A standalone task retains its full accounting number in its own title, for example `🟡 0.13 / Update API reference`; mixed active work can display `0,2,8`. A genuine historical `00` sprint remains a separate exact spelling, so `0,00,2` is valid. The standalone `0` creates no sprint, chat group or registry.
- Each managed chat applies its confirmed own status icon in an active authorized turn, using its admitted recording/reporting path and the existing exact-ID safeguards. A readiness-only initializer is not a substantive work grant or evidence of work start. Author DONE, a report or a transport acknowledgement is not manager acceptance.
- An active manager always keeps leading `🧑‍💼`. Its own blocking wait follows as a second icon rather than replacing it: `🧑‍💼 🙋` for a human, `🧑‍💼 💤` for another chat or delegated model, and `🧑‍💼 ⏳` for a tool/network-only wait, with the precedence below. This second icon precedes any applicable archive `☑️`. For example, a verified chief among several verified active managers can display `🧑‍💼 💤 0,00,8 / ⭐ MANAGER — Description`. An own wait hides any subordinate-question segment without clearing or resolving its recorded reason. Task-chat state and wait icons and the former-manager `👤` display are unchanged.

- `⭐` appears immediately before the uppercase literal `MANAGER` only for the verified chief among several verified active managers, as in `🧑‍💼 8 / ⭐ MANAGER — Description`. It is not assigned to every manager, and a sole active manager has no `⭐` display marker. Chief selection and scope ownership remain separate.
- `✅` means accepted success only after actual manager acceptance following the required independent review, with the canonical task record and delivery/read evidence. It supersedes the former `✔️` acceptance display.
- `☑️` has two deliberately recorded uses: authorized terminal closure without success, or a separate explicit archival display. Terminal closure requires an authorized final decision and a separately recorded reason and actual result. Archival display requires an explicit Archive-menu action or an unambiguous direct human archive instruction; finishing work, DONE, silence or age is insufficient. The glyph alone proves neither acceptance nor a host archive action.
- A temporary or bare Stop, pause, deferral, block, wait, transient failure or UNKNOWN operation is not terminal closure. Archiving also does not erase the underlying task state or prove termination and cleanup. Current `☑️` terminal rules supersede the former `❌`/`🚫` cancellation displays; historical release entries remain historical.

### Waiting states and useful work

- Use `💤` for an actual blocking wait for another chat's response, result, review, acceptance or action—including root, executor or reviewer—or for a supporting stateless delegated model, when the needed result is not ready and no other useful authorized path remains. A persistent second chat or a separate review task is not required.
- Use `🙋` for a blocking human answer, choice or approval. When several waits coexist, precedence is `🙋`, then `💤`, then `⏳`. Use `⏳` for a concrete non-human, non-chat wait such as tool, service or network recovery or exact-operation reconciliation.
- A pending answer without blocking effect sets no wait icon while useful independent authorized work continues. Waiting icons do not resolve ownership, Stop, pause, UNKNOWN, approval or non-replay state.

### Package scope and compatibility

The bundled worker, native and Python code and the runtime requirements are unchanged from 0.6.16. No transport behavior fix or new Windows, live-GUI, runtime, model-serving or universal-host compatibility is claimed. Existing host prerequisites and route-specific evidence requirements still apply; see the [quick start](../quickstart.md).

## Русский

TokenBand 0.6.20 — накопленное обновление инструкций. Оно включает изменения, ранее обозначенные как 0.6.17, 0.6.18 и 0.6.19, а также итоговые правила работы менеджера и отображения статусов. Промежуточные изменения описаны здесь в составе 0.6.20, а не как отдельные загрузки.

### Работа менеджера без периодической автоматизации

- Проверка состояния менеджером входит в фактический разрешённый рабочий ход. Установка скилла, создание или принятие роли менеджера и её продолжение не создают и не требуют таймер, периодическое расписание, многоразовый ежечасный запрос, cron, демон или обещание самопробуждения.
- Пока остаются полезная разрешённая работа, выполняющееся назначение или необходимый приём результата, менеджер продолжает тот же фактический ход: поддерживаемое конечное наблюдение, проверку и приём результата, применимые независимые этапы проверки и каждый разрешённый готовый следующий шаг. Ответ о статусе или сохранённый отчёт сами по себе не завершают эту цель координации. Бесконечный неизменный опрос и взаимный цикл подтверждений не разрешаются.
- Изменение инструкций не отключает и не удаляет существующий таймер. Действие с конкретным ранее созданным таймером остаётся отдельной разрешённой операцией среды и не затрагивает другую автоматизацию пользователя.
- Stop выполняется немедленно. Несбрасываемый срок неопределённости 900 секунд и прежние правила восстановления, исходных владельцев, фактических отказов, UNKNOWN и запрета повторного выполнения сохраняются.

### Заголовки задач и менеджеров

- Активная автономная работа добавляет ровно один `0` в отображение активной работы менеджера. Автономная задача сохраняет полный учётный номер в заголовке своего чата, например `🟡 0.13 / Обновить справку API`; смешанная активная работа может отображаться как `0,2,8`. Реальный исторический спринт `00` остаётся отдельным точным написанием, поэтому допустимо `0,00,2`. Автономный `0` не создаёт спринт, группу чатов или реестр.
- Каждый управляемый чат применяет подтверждённую собственную иконку состояния в активном разрешённом ходе через предоставленный ему путь записи или отчёта и с прежними exact-ID ограничениями. Инициализатор готовности не является разрешением на содержательную работу или доказательством её начала. DONE автора, отчёт или транспортное подтверждение не равны приёмке менеджером.
- Активный менеджер всегда сохраняет ведущую иконку человека `🧑‍💼`. Его собственное блокирующее ожидание обозначается второй иконкой, а не заменой первой: `🧑‍💼 🙋` для человека, `🧑‍💼 💤` для другого чата или делегированной модели и `🧑‍💼 ⏳` для ожидания только инструмента или сети, с приоритетом, описанным ниже. Эта вторая иконка предшествует любому применимому архивному `☑️`. Например, подтверждённый главный менеджер среди нескольких подтверждённых активных менеджеров может иметь заголовок `🧑‍💼 💤 0,00,8 / ⭐ MANAGER — Описание`. Собственное ожидание скрывает сегмент подчинённого вопроса, но не удаляет и не разрешает записанную причину этого вопроса. Иконки состояния и ожидания чатов задач, а также отображение роли бывшего менеджера `👤`, не меняются.

- `⭐` ставится непосредственно перед заглавным литеральным `MANAGER` только у подтверждённого главного менеджера среди нескольких подтверждённых активных менеджеров, например `🧑‍💼 8 / ⭐ MANAGER — Описание`. Знак не назначается каждому менеджеру, а единственный активный менеджер отображается без `⭐`. Выбор главного менеджера и владение областями работы остаются разными фактами.
- `✅` означает принятый успешный результат только после фактической приёмки менеджером по завершении необходимой независимой проверки, с канонической записью задачи и подтверждёнными доставкой и прочтением для точной задачи и чата. Это обозначение заменяет прежний значок приёмки `✔️`.
- У `☑️` есть два отдельно фиксируемых применения: согласованное окончательное закрытие без успеха либо отдельное явное архивное отображение. Окончательное закрытие требует разрешённого финального решения и отдельной записи причины и фактического результата. Архивное отображение требует явного действия Archive в меню либо однозначной прямой просьбы человека архивировать; завершение работы, DONE, молчание или возраст чата недостаточны. Сама иконка не доказывает ни приёмку, ни архивное действие приложения.
- Временный или простой Stop, пауза, откладывание, блокировка, ожидание, временный сбой или UNKNOWN-операция не являются окончательным закрытием. Архивирование также не стирает фактическое состояние задачи и не доказывает завершение процессов и очистку. Текущие правила `☑️` заменяют прежние обозначения отмены `❌`/`🚫`; исторические записи выпусков остаются историей.

### Ожидание и полезная работа

- `💤` обозначает фактическое блокирующее ожидание ответа, результата, проверки, приёмки или действия другого чата — включая root, исполнителя или проверяющего — либо вспомогательной stateless делегированной модели, когда нужный результат ещё не готов и другого полезного разрешённого пути нет. Постоянный второй чат или отдельная задача проверки для этого не требуются.
- `🙋` обозначает блокирующий ответ, выбор или разрешение человека. При нескольких ожиданиях приоритет таков: `🙋`, затем `💤`, затем `⏳`. `⏳` применяется к конкретному ожиданию не человека и не чата, например восстановления инструмента, службы или сети либо сверки точной операции.
- Ожидающийся ответ без блокирующего эффекта не устанавливает иконку ожидания, пока продолжается полезная независимая разрешённая работа. Иконки ожидания не разрешают состояние владения, Stop, паузы, UNKNOWN, разрешений или запрета повторного выполнения.
